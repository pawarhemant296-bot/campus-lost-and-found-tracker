THE SMART MATCHING ENGINE
SIHIdea Submission

Weighted signals (never relies on an exact name)

Item / category similarity25%
Description similarity25%
Location similarity20%
Date / time proximity15%
Image similarity (dHash)15%

Techniques

  • Synonym lexicon — phone›mobile›cell, wallet›purse, canteen›cafeteria›mess, colour & place families.
  • Text similarity — token overlap + Jaccard + character-bigram cosine (tolerates typos & different wording).
  • Calibration curve — same-object descriptions share only 30–45% of words; mapped to real confidence.
  • Date proximity — exponential decay across a configurable window.
  • Image similarity — 64-bit perceptual difference hash, Hamming distance.
  • Weight re-normalisation — a missing factor (no photo) is dropped and the rest rescale.

Worked example — from the live demo

Ownership verification

  • Finder stores private questions; the API returns only the questions, never the answers.
  • Claimant answers are auto-scored by the same engine — advisory only.
  • Genuine owner ~89% vs impostor ~2% in testing; a human always decides.
  • Rejections can be escalated as a dispute to an admin.

FEASIBILITY AND VIABILITY
SIHIdea Submission

Feasibility

TraceBack is highly feasible — it is already a complete, working full-stack build, verified end to end (44 automated checks over the whole lost›found›match›return journey).

Technical
Standard, well-supported stack (Node, React, SQLite). Runs on any laptop with zero database setup and no C++ toolchain — the DB auto-uses Node's built-in SQLite.
Operational
Simple web UI any student can use; the matching, verification and status tracking are automatic. A single command boots the whole app.
Financial
Near-zero running cost: SQLite + local image hashing need no paid APIs. A low-cost MVP is already done.
Deployable now
Single Node process serves the built client; hostable on any free/low-cost PaaS or a campus server.

Viability

Real, recurring need
Every campus, office and transit hub loses items daily; the current process is scattered notice boards and chat groups.
Privacy-first trust model
Masked identities + private ownership questions make institutions comfortable adopting it officially.
Modular & scalable design
Plain-SQL data layer swaps to PostgreSQL for multi-campus; the matching engine is an isolated module ready for heavier ML.
Adoption paths
Deploy per college / company; integrate with existing ID systems; extend to city-level public lost-and-found.

Sustainability

Institutional licensing, optional premium notifications, and analytics for facilities teams — with no dependency on paid third-party services.
